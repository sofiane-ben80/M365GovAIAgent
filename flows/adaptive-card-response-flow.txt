================================================================================
  POWER AUTOMATE FLOW: Adaptive Card Response Flow
  Purpose : Process inline action responses from Teams adaptive cards and route
            the resulting update to the governance lists.
  Trigger : Teams adaptive card response / Power Automate action submit
  Returns : action result payload
================================================================================

INPUTS
  - actionType: text
  - siteUrl: text
  - siteItemId: number
  - callerUPN: text
  - confirmationText: text
  - targetOwnerUPN: text

OUTPUTS
  - success: boolean
  - actionStatus: COMPLETED | PENDING | REJECTED | FAILED
  - message: text

FLOW STEPS
──────────

STEP 0 — Validate submit payload
  1. Ensure actionType and siteUrl are present.
  2. Ensure the user has permission to act on the site.
  3. For deletion, require confirmationText = CONFIRM.

STEP 1 — Route to the right action
  1. If actionType = CERTIFY, call the Action Callback Flow with CERTIFY.
  2. If actionType = ARCHIVE, call the Action Callback Flow with ARCHIVE.
  3. If actionType = DELETE, call the Action Callback Flow with DELETE-REQUESTED.
  4. If actionType = ASSIGN-OWNERS, call the Action Callback Flow with ASSIGN-OWNERS.

STEP 2 — Handle response
  1. Translate success/failure into a user-friendly Teams message.
  2. If the result is pending, tell the user who will review it next.
  3. If the result failed, show the safe fallback message.

STEP 3 — Return result
  1. Update the adaptive card conversation thread if supported.
  2. Return a compact payload for auditing.

IMPLEMENTATION NOTES
  1. This flow is the response handler for proactive notification buttons.
  2. It should share the same action contract as the Action Callback Flow.
